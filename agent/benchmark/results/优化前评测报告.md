## 3. 失败原因分类

### 3.1 Sandbox 数据库覆盖不足（影响 5 条 case）

**严重程度**: ⭐⭐⭐⭐⭐ (核心瓶颈)

Agent 通过 LLM 知识和网络搜索生成了真实存在的餐厅/景点/路线，但 sandbox 数据库基于 2022 年静态 CSV，覆盖范围有限。

| idx | 具体问题 |
|-----|----------|
| 0 | 景点 "Sinnissippi Park & Gardens" 不在 attractions.csv |
| 1 | 自驾路线 "Kansas City → Pensacola" 在 distance.csv 中无记录 |
| 3 | 自驾路线 "New Orleans → Louisville" 在 distance.csv 中无记录 |
| 4 | 餐厅 "Snooze, an A.M. Eatery" 不在 Denver 的 restaurants 表中 |
| 5 | 餐厅 "Mi Tierra Cafe & Panaderia" 不在 San Antonio 的 restaurants 表中 |
| 9 | 景点 "Independence Hall" 不在 Philadelphia 的 attractions 表中 |

**分析**: 这是评测框架本身的局限性，而非 Agent 能力问题。Agent 生成的地点在现实中大多真实存在，但 sandbox 数据库未收录。

### 3.2 计划解析失败（影响 2 条 case）

**严重程度**: ⭐⭐⭐⭐

| idx | 路线 | 问题 |
|-----|------|------|
| 6 | Santa Ana → Montana (Billings + Helena) | Agent 输出了完整的 markdown 计划，但 LLM 解析为 null |
| 7 | Baton Rouge → Texas (Abilene + Amarillo) | 同上 |

**分析**: 5 天行程的 markdown 输出较长（idx 6 约 8000+ tokens），可能超出解析 LLM 的有效上下文窗口，或格式不符合预期的 8-field JSON schema。两例均为 easy 级别 5 天行程。

### 3.3 结构性约束违规（影响 3 条 case）

**严重程度**: ⭐⭐⭐

| idx | 违规类型 | 具体描述 |
|-----|----------|----------|
| 1 | 餐厅重复 | Watershed Cafe 在 Day1 晚餐和 Day2 晚餐重复使用 |
| 8 | 非闭环行程 | Memphis → State College → Johnstown，最后一天返回 Memphis 但 parsed_plan 仅解析到 Day3 |
| 8 | 住宿最低天数 | Johnstown 住宿要求最少 2 晚，实际只住 1 晚 |
| 9 | 交通方式冲突 | 去程 Flight + 回程 Self-driving 混合使用 |

**分析**: 这些是 Agent 规划逻辑的真实缺陷。重复使用餐厅说明 Agent 未跟踪已推荐的地点；交通冲突说明 Agent 未保持一致性。

### 3.4 城市归属错误（影响 1 条 case）

**严重程度**: ⭐⭐

| idx | 问题 |
|-----|------|
| 4 | Day3 午餐在 Morrison（Denver 郊区），evaluator 认为不在当前城市 "Denver" 范围内 |

**分析**: Agent 在规划 Red Rocks 一日游时选择了 Morrison 镇的餐厅，地理上合理但不符合 evaluator 的严格城市匹配逻辑。

## 6. 硬约束分析

由于大多数 case 在常识约束阶段就失败了（`is_not_absent` 或 `is_valid_information_in_sandbox` 未通过），硬约束评估被跳过。仅有 idx 2 进入硬约束评估并全部通过。

硬约束涉及：
- 预算 (valid_cost)
- 烹饪偏好 (valid_cuisine)
- 住宿规则 (valid_room_rule)
- 房型 (valid_room_type)
- 交通限制 (valid_transportation)

## 7. 结论与优化方向

### 核心发现

1. **Agent 生成能力良好**: 100% 交付率，所有 case 都生成了完整的旅行计划
2. **Sandbox 匹配是最大瓶颈**: 50% 的失败源于名称不在静态数据库中
3. **解析器对长行程支持不足**: 5 天行程的解析失败率高于 3 天
4. **规划逻辑存在缺陷**: 餐厅重复、交通冲突等结构性问题

### 建议优化方向

| 优先级 | 方向 | 预期收益 |
|--------|------|----------|
| P0 | 让 Agent 在生成计划时查询 sandbox 数据库，只推荐库中存在的餐厅/景点/住宿 | 解决 50% 的失败 |
| P1 | 优化 plan parser 对长行程 (5天+) 的支持，或分段解析 | 解决 20% 的失败 |
| P1 | 在 Agent prompt 中加入约束检查逻辑（不重复餐厅、交通一致性等） | 解决 30% 的失败 |
| P2 | 放宽 evaluator 的城市匹配逻辑（允许郊区/近郊） | 边际改善 |
