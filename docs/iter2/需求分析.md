# 需求分析文档

## 1. 项目概述

### 1.1 项目名称
TripAgent - 智能旅游规划助手

### 1.2 项目背景
本项目是一个基于大语言模型（LLM）驱动的智能旅游规划Agent应用，采用ReAct + Plan-and-Execute混合推理框架，为用户提供智能化的旅行规划服务。

### 1.3 项目目标
为用户提供一个具备自主思考和行动能力的智能旅游规划助手，能够理解用户的自然语言请求，自动规划旅行方案，并通过调用外部工具获取实时信息，最终生成个性化的旅行计划。

## 2. 背景与目标

### 2.1 业务背景
随着旅游行业的数字化转型，用户对个性化、智能化旅行规划的需求日益增长。传统的旅行规划方式耗时费力，用户需要在多个平台间切换获取信息。本项目旨在打造一个一站式智能旅行规划助手，通过自然语言交互，自动完成目的地推荐、行程规划、天气查询等任务。

### 2.2 技术背景
项目采用ReAct（Reasoning + Acting）架构，使Agent具备自主思考和行动能力。Agent能够理解用户需求，规划执行步骤，调用外部工具获取信息，并根据反馈进行自我修正。

### 2.3 目标
- 构建具备规划和思考能力的智能Agent
- 实现至少2个主题相关的外部工具（如搜索、天气查询）
- 具备自我修正能力，能够捕获并处理异常
- 可视化内部状态流转，提升用户体验

## 5. 功能需求（Functional Requirements）

### 5.1 用户管理与鉴权
- FR-001: 系统应支持用户注册、登录、密码修改功能
- FR-002: 支持基于JWT的会话管理
- FR-003: 用户信息（头像、昵称）可编辑

### 5.2 Agent核心能力
- FR-004: 支持自然语言理解，解析用户旅行需求
- FR-005: 具备规划能力（MetaPlanner），能够拆解复杂任务
- FR-006: 具备推理能力（ReAct），能够进行多步思考
- FR-007: 具备反思能力（Reflection），能够自我修正错误
- FR-008: 支持两种模式：plan模式（仅生成计划）、agent模式（执行计划）

### 5.3 外部工具能力
- FR-009: 集成Web搜索工具（Serper），获取目的地信息
- FR-010: 集成天气查询工具，获取旅行期间天气
- FR-011: 集成文档解析工具（FileParser），支持解析PDF/Word/TXT等格式
- FR-012: 支持工具动态注册与调用

### 5.4 LLM服务封装
- FR-013: 提供统一的LLM抽象接口，支持多厂商切换
- FR-014: 支持请求限流与重试策略
- FR-015: 支持流式响应输出

### 5.5 后端API
- FR-016: 提供旅行计划的CRUD操作
- FR-017: 提供社区帖子功能（发布、评论、点赞）
- FR-018: 提供目的地数据接口
- FR-019: 支持对话历史存储

### 5.6 前端交互
- FR-020: 支持SSE实时事件，展示Agent思考过程
- FR-021: 提供AI计划视图，展示生成的旅行计划
- FR-022: 提供社区视图，展示用户分享的旅行经历
- FR-023: 提供用户档案视图，展示个人信息和收藏

### 5.7 可视化要求
- FR-024: 可视化Agent内部状态流转（Thought, Action, Observation）
- FR-025: 展示规划步骤拆解过程
- FR-026: 展示工具调用历史与结果

## 6. 非功能需求（Non-Functional Requirements）

### 6.1 性能要求
- NFR-001: 常规请求响应时间 < 500ms（不含LLM外部调用）
- NFR-002: 长任务通过SSE分段回传，每段延迟 < 2秒
- NFR-003: LLM调用超时时间 < 60秒

### 6.2 可用性要求
- NFR-004: 关键服务故障时应降级而非整体失败
- NFR-005: 工具调用失败时Agent能够自动重试
- NFR-006: 系统全年可用性 ≥ 99%

### 6.3 可扩展性要求
- NFR-007: 模块化设计，LLM提供者可独立替换
- NFR-008: 工具注册机制支持热插拔
- NFR-009: 评估模块可独立迭代

### 6.4 安全性要求
- NFR-010: 敏感配置存储在配置文件中，不硬编码
- NFR-011: 上传文件类型和大小限制（最大50MB）
- NFR-012: 防止路径遍历攻击
- NFR-013: 用户密码加密存储（BCrypt）

### 6.5 可观测性要求
- NFR-014: 关键路径记录日志，支持错误追溯
- NFR-015: 建议接入应用监控（Prometheus/Grafana）
- NFR-016: 记录Agent决策过程日志，便于调试

## 7. 主要用例（Use Cases / 用户故事）

### 7.1 用例清单

| 用例ID | 用例名称 | 执行者 | 描述 |
|--------|----------|--------|------|
| UC-001 | 生成旅行计划 | 用户 | 用户输入自然语言请求，Agent生成详细旅行计划 |
| UC-002 | 查询目的地天气 | Agent | Agent调用天气工具获取旅行期间天气信息 |
| UC-003 | 搜索景点信息 | Agent | Agent调用搜索工具获取景点推荐和攻略 |
| UC-004 | 解析旅行文档 | 用户/Agent | 上传并解析旅行相关文档作为参考 |
| UC-005 | 保存旅行计划 | 用户 | 将生成的旅行计划保存到个人空间 |
| UC-006 | 分享旅行计划 | 用户 | 将旅行计划分享到社区 |
| UC-007 | 查看社区帖子 | 用户 | 浏览其他用户分享的旅行经历
| UC-008 | 评论点赞 | 用户 | 对社区帖子进行评论和点赞 |

### 7.2 详细用例：UC-001 生成旅行计划

**前置条件**：用户已登录系统

**基本流程**：
1. 用户在前端输入旅行需求（如："帮我规划一个3天的北京之旅"）
2. 前端将请求发送到后端
3. 后端调用Agent服务
4. Agent进行以下处理：
   a. 解析用户请求，识别目的地和天数
   b. 调用MetaPlanner生成规划步骤
   c. 根据规划调用搜索工具获取景点信息
   d. 调用天气工具获取天气信息
   e. 综合所有信息生成完整旅行计划
5. Agent通过SSE流式返回中间状态（Thought、Action、Observation）
6. 前端实时展示Agent思考过程
7. 最终展示完整旅行计划

**异常流程**：
- 如果工具调用失败，Agent进行反思并重新尝试
- 如果LLM调用超时，返回友好错误提示

**后置条件**：旅行计划生成成功并展示给用户

## 8. 数据需求

### 8.1 核心实体

| 实体 | 说明 | 存储方式 |
|------|------|----------|
| User | 用户信息 | MySQL |
| TravelPlan | 旅行计划 | MySQL |
| ChatConversation | 对话历史 | MySQL |
| CommunityPost | 社区帖子 | MySQL |

| LikeRecord | 点赞记录 | MySQL |

### 8.2 数据模型关系
- User 1:N TravelPlan（用户拥有多个旅行计划）
- User 1:N CommunityPost（用户发布多个帖子）
- CommunityPost 1:N Comment（帖子有多个评论）
- CommunityPost 1:N LikeRecord（帖子有多个点赞）
- TravelPlan 1:N PlanHighlight（计划包含多个亮点）

## 9. 接口与集成

### 9.1 外部接口

| 接口 | 路径 | 方法 | 说明 |
|------|------|------|------|
| 健康检查 | /health | GET | 检测服务状态 |
| Agent对话 | /api/agent/chat | POST | 主对话端点，返回SSE流 |
| 用户注册 | /api/auth/register | POST | 用户注册 |
| 用户登录 | /api/auth/login | POST | 用户登录 |
| 获取旅行计划列表 | /api/travel/plans | GET | 获取用户旅行计划 |
| 创建旅行计划 | /api/travel/plans | POST | 创建旅行计划 |
| 获取社区帖子 | /api/community/posts | GET | 获取社区帖子列表 |
| 发布社区帖子 | /api/community/posts | POST | 发布帖子 |

### 9.2 内部集成

| 模块 | 集成方式 |
|------|----------|
| Agent与后端 | HTTP + SSE |
| 前端与后端 | HTTP + SSE + WebSocket |
| Agent与LLM | REST API |
| Agent与工具 | Python接口调用 |
| 评估服务与后端 | REST API（带Token鉴权） |

### 9.3 SSE事件格式

Agent通过SSE返回以下事件类型：
- `plan`: 规划步骤
- `thought`: 思考过程
- `tool_call`: 工具调用
- `observation`: 工具返回结果
- `message`: 最终回复
- `error`: 错误信息
- `done`: 完成标志
