## 三、核心组件设计

### 3.1 PlanChecker 子 Agent（结构验证）

**文件**: `services/plan_checker.py`

PlanChecker 是迭代三的核心优化之一。它在 Agent 调用 `finish` 输出最终答案前，对旅行计划进行结构合规性检查，不合规则触发 Reflexion 自我修正循环。

#### 设计动机

通过 TravelPlanner Benchmark 评测发现 **30% 的失败 Case 因结构性约束违规**导致（餐厅重复、非闭环行程、交通冲突等）。这些问题不是搜索信息不足，而是 Agent 规划逻辑的缺陷。PlanChecker 通过"检查-反馈-修正"的 Reflexion 模式解决这类问题。

#### 类设计

```python
class PlanChecker:
    """LLM-based plan structural compliance checker."""

    _CHECKER_SCHEMA = {
        "type": "object",
        "properties": {
            "compliant": {"type": "boolean"},
            "violations": {
                "type": "array",
                "items": {"type": "string"},
            },
        },
        "required": ["compliant", "violations"],
        "additionalProperties": False,
    }

    def __init__(self, llm: LLMService):
        self._llm = llm

    def check(self, query: str, plan_markdown: str) -> tuple[bool, list[str]]:
        """检查旅行计划的结构合规性。"""
        result = self._llm.chat_json(
            messages=[
                {"role": "system", "content": _CHECKER_PROMPT},
                {"role": "user", "content": f"User query:\n{query}\n\nPlan:\n{plan_markdown}"},
            ],
            schema=self._CHECKER_SCHEMA,
            temperature=0.1,
        )
        return result.get("compliant", True), result.get("violations", [])
```

#### 检查规则（8 条）

| 编号 | 规则 | 检查内容 |
|------|------|----------|
| 1 | 闭环行程 | 最后一天必须返回出发城市 |
| 2 | 餐厅不重复 | 整个行程中不得推荐同一家餐厅 |
| 3 | 景点不重复 | 整个行程中不得推荐同一个景点 |
| 4 | 交通一致性 | 城市间移动必须合理，交通方式一致 |
| 5 | 住宿合理性 | 住宿城市必须在行程路径上 |
| 6 | 天数覆盖 | 必须覆盖所有天数 |
| 7 | 城市覆盖 | 必须覆盖所有目的地城市 |
| 8 | 餐饮完整 | 每天必须有早/午/晚三餐 |

#### Reflexion 集成流程

```
ReAct Agent 调用 finish(answer)
        │
        ▼
  PlanChecker.check(query, answer)
        │
   ┌────┴────┐
   │         │
compliant  violations
   │         │
   ▼         ▼
输出答案   格式化违规反馈
             │
             ▼
   注入 tool result 到对话历史
   {"status": "validation_failed",
    "violations": [...],
    "message": "Please revise..."}
             │
             ▼
   ReAct Agent 下一轮看到违规反馈
   → 自主修正计划 → 再次 finish
             │
        (最多 2 轮)
```

#### 关键设计决策

| 决策 | 理由 |
|------|------|
| LLM-based 而非确定性验证 | 不依赖特定数据库，适用于真实产品场景 |
| `temperature=0.1` | 检查器本身需要高确定性 |
| 异常时默认放行 | 检查器出错不阻塞流程（`compliant=True`） |
| 最多 2 轮重试 | 平衡质量与延迟 |
| 独立服务组件 | 与 ReAct Agent 解耦，可独立测试和替换 |

#### 评测效果

| 指标 | 优化前 | 优化后 | 变化 |
|------|--------|--------|------|
| 最终通过率 | 10% (1/10) | 30% (3/10) | **3 倍提升** |
| 结构违规 | 30% (3/10) | 0% (0/10) | **完全消除** |

### 3.2 Skill 系统（技能管理）

**文件**: `services/tool_registry.py`（ActivateSkillTool, CreateSkillTool）

基于 Anthropic Skills 范式，实现三级渐进式披露的技能管理引擎。

#### 三级渐进式披露

```
Level 1: 元数据常驻
  Agent 初始化时，仅将已启用 Skill 的 name + description
  注入 System Prompt 的 "Available Skills" 列表
        │
        ▼
Level 2: 按需动态激活
  LLM 判断适合使用某 Skill → 调用 activate_skill 工具
  → 加载 SKILL.md 完整指令到对话上下文
        │
        ▼
Level 3: 精准工具调用
  Skill 注册的 Python 脚本 → 作为独立 Tool 被 LLM 调用
  （如 budget_calculator.py）
```

| `budget-optimizer` | 用户提到"省钱"、"预算有限" | 3:2:3:2 消费分配法则，高成本景点替换 |
| `packing-helper` | 用户问"带什么"、"行李清单" | 根据天气+天数+同行人生成结构化清单 |
| `skill-creator` | 用户要求创建新技能 | 对话式引导用户定义 Skill 元数据和指令 |

#### 混合检索策略

```python
def search(self, query: str, namespace: str, top_k: int = 5) -> list:
    # 1. 稠密向量检索（语义相似度）
    dense_results = self._store.search_dense(query_embedding, top_k)

    # 2. 稀疏 BM25 检索（关键词匹配）
    sparse_results = self._store.search_sparse(query, top_k)

    # 3. 混合排序（RRF 或加权融合）
    merged = reciprocal_rank_fusion(dense_results, sparse_results)

    # 4. Rerank（可选）
    if self._reranker:
        merged = self._reranker.rerank(query, merged)

    return merged[:top_k]
```

### 3.5 高德地图集成

#### 三级坐标查找

```python
def get_coordinates(self, city: str, location_name: str) -> tuple[float, float]:
    # Level 1: 本地地标库（硬编码常用坐标）
    key = f"{city}_{location_name}"
    if key in LOCAL_LANDMARKS:
        return LOCAL_LANDMARKS[key]

    # Level 2: 高德地理编码 API
    result = self.geocode(location_name, city)
    if result:
        return result

    # Level 3: 城市中心 + 随机偏移（兜底）
    base = CITY_BASES.get(city, CITY_BASES["default"])
    return (base[0] + random.uniform(-0.01, 0.01),
            base[1] + random.uniform(-0.01, 0.01))
```

#### 计划解析与坐标补全

`plan_parser.py` 在将 Markdown 旅行计划解析为结构化 JSON 后，对每个活动调用 `AMapClient.get_coordinates()` 补全经纬度坐标，并注入 UUID 供前端地图标记使用。

def extract_plan_from_markdown(markdown: str, destination: str) -> dict:

### 3.6 上下文压缩

**文件**: `services/react_agent.py`（`_maybe_compress_context`）

#### 触发条件

当 ReAct 循环中消息的估算 token 数超过 `max_context_tokens` 的 `compress_threshold`（默认 80%）时自动触发。

#### 压缩策略

```python
def _maybe_compress_context(self, messages: list) -> list:
    estimated_tokens = self._estimate_tokens(messages)
    if estimated_tokens < self._max_context_tokens * self._compress_threshold:
        return messages  # 未达阈值，不压缩

    # 保留：系统消息 + 最近 N 轮对话
    system_msgs = [m for m in messages if m["role"] == "system"]
    recent_msgs = messages[-(self._compress_keep_last * 2):]
    old_msgs = messages[len(system_msgs):-len(recent_msgs)]

    # 用 LLM 生成摘要（temperature=0.1）
    summary = self._llm.chat(
        messages=[{"role": "user", "content": f"Summarize:\n{old_msgs}"}],
        temperature=0.1,
    )

    # 注入摘要
    summary_msg = {"role": "system", "content": f"Conversation summary:\n{summary}"}
    return system_msgs + [summary_msg] + recent_msgs
```

#### SSE 事件

压缩发生时发送 `context_compressed` 事件，前端可展示提示：

```json
{"type": "context_compressed", "content": "已压缩早期对话，保留最近 6 轮", "metadata": {}}
```

### 3.7 模型竞技场

**后端**: `ModelArenaService` + `ModelArenaController`
**前端**: `ModelLeaderboardView`

#### 工作原理

1. 用户发起对比请求
2. 后端随机选择 2 个模型，使用相同 query 并行调用
3. 前端并排展示两个模型的 SSE 流式输出
4. 用户投票选择更好的回答
5. 投票记录存入 `model_arena_votes` 表
6. 基于 Bradley-Terry 算法计算排行榜

#### Bradley-Terry 评分

```
P(model_A wins) = exp(β_A) / (exp(β_A) + exp(β_B))

其中 β_A, β_B 为模型的 Bradley-Terry 参数，
通过最大似然估计从投票历史中计算。
```

## 四、推理框架详解（增强版）

### 4.1 ReAct + PlanChecker + Reflexion

迭代三将原有的 ReAct + Reflection 三层推理框架扩展为四层：

```
请求进入
  │
  ├── mode="agent":
  │     [可选] MetaPlanner 生成计划
  │     → ReActAgent 执行推理
  │     → PlanChecker 结构验证
  │       ├── 合规 → 输出
  │       └── 不合规 → Reflexion 修正（最多 2 轮）
  │
  └── mode="reflection":
        [可选] MetaPlanner 生成计划
        → ReflectionAgent = ReAct + 自我评估
        → PlanChecker 结构验证
          ├── 合规 → 输出
          └── 不合规 → Reflexion 修正（最多 2 轮）
```

### 4.2 System Prompt 增强

迭代三的 System Prompt 包含以下新增部分：

```
You are a travel planning assistant agent.

Available Tools:
{tools}

Available Skills:
- budget-optimizer: When user mentions budget optimization...
- packing-helper: When user asks about packing list...
- skill-creator: When user wants to create a new skill...

Personal Memories:
- User prefers budget-friendly options
- Has a 5-year-old child, needs kid-friendly activities
- Previously visited Beijing, interested in cultural sites

Execution plan to follow:
{plan}

Follow the ReAct pattern...
```

### 4.3 完整执行流程

```python
async def run(self, query: str, ...):
    # 1. 获取用户记忆
    memory = self._memory_service.fetch_latest(user_id)

    # 2. 获取已启用技能
    skills = self._fetch_active_skills()

    # 3. 构建 System Prompt（注入记忆 + 技能）
    system_msg = self._build_system_prompt(memory, skills, plan)

    # 4. ReAct 循环
    for step in range(max_iterations):
        # THINK: LLM 思考
        response = self._llm.chat_with_tools(messages, tools)

        # ACT: 工具调用
        for tool_call in response.tool_calls:
            if tool_call.name == "finish":
                answer = tool_call.arguments["answer"]

                # PlanChecker 验证
                if check_retries < max_check_retries:
                    compliant, violations = self._plan_checker.check(query, answer)
                    if not compliant:
                        # 注入违规反馈，继续循环
                        check_retries += 1
                        messages.append(feedback)
                        break

                # 合规 → 输出
                yield self._emit("answer", answer)
                break

            # 其他工具调用...
            result = self._execute_with_retry(tool_call)

        # OBSERVE: 观察结果
        messages.append(observation)

        # 上下文压缩检查
        messages = self._maybe_compress_context(messages)

    # 5. 记忆同步（异步）
    self._memory_service.sync(user_id, extraction)
```

## 八、错误处理与容错（增强版）

### 8.1 新增容错层级

| 层级 | 异常场景 | 处理方式 |
|------|----------|----------|
| **PlanChecker 层** | 检查器自身异常 | 默认放行（`compliant=True`） |
| **记忆层** | 记忆提取失败 | 跳过本次同步，不影响对话 |
| **知识层** | Milvus 不可用 | 降级为无 RAG 模式 |
| **技能层** | 技能加载失败 | 返回错误信息，Agent 继续推理 |
| **地图层** | 高德 API 不可用 | 降级为本地地标库 + 随机偏移 |

### 8.2 PlanChecker 降级策略

```python
def check(self, query: str, plan_markdown: str) -> tuple[bool, list[str]]:
    try:
        result = self._llm.chat_json(...)
        return result.get("compliant", True), result.get("violations", [])
    except Exception:
        # 检查器出错时默认放行，不阻塞流程
        return True, []
```
