# 需求分析文档（迭代三）

## 1. 项目概述

### 1.1 项目名称
TravelMind - 智能旅游规划助手

### 1.2 项目背景
迭代二完成了基于 ReAct + Plan-and-Execute 混合推理框架的智能旅游规划 Agent 核心能力。迭代三的目标是将 Agent 从"能用"推向"好用"，聚焦**产品化**和**定制化**两个方向：让 Agent 具备用户可配置的技能系统、跨对话的长期记忆、结构化输出验证、知识检索增强等产品级能力。

### 1.3 迭代三核心目标

| 方向 | 目标 | 关键成果 |
|------|------|----------|
| **产品化** | Agent 具备完整的产品级能力 | Skill 管理、长期记忆、PlanChecker 结构验证 |
| **定制化** | 用户可按需配置 Agent 行为 | 自定义技能、偏好记忆、工具开关 |
| **能力优化** | 提升规划质量和稳定性 | AI 随机性应对、Benchmark 评测驱动优化 |
| **生态扩展** | 接入外部服务和知识 | 高德地图、RAG 知识库、模型竞技场 |

## 2. 背景与目标

### 2.1 业务背景

迭代二的 Agent 已经能够完成基本的旅行规划任务，但在真实产品场景中暴露以下问题：

| 问题 | 表现 | 影响 |
|------|------|------|
| **输出不稳定** | 相同请求多次调用产生不同结果 | 用户体验不可预测 |
| **无个性化** | Agent 不记忆用户偏好，每次从零开始 | 重复沟通，效率低 |
| **结构缺陷** | 生成的计划可能出现重复餐厅、非闭环行程等 | 输出质量不可靠 |
| **工具单一** | 仅有搜索和文件解析，缺乏地图、知识库等 | 规划深度有限 |
| **不可定制** | 用户无法调整 Agent 的技能和行为 | 缺乏个性化空间 |

### 2.2 技术背景

迭代二建立了以下技术基础，迭代三在此之上进行扩展：

- **ReAct Agent**：Think-Act-Observe 推理循环
- **MetaPlanner**：Plan-and-Execute 计划生成
- **Reflection Agent**：自我评估与改进
- **Tool Registry**：策略模式的工具注册中心
- **SSE 流式输出**：实时状态推送

### 2.3 目标

- 实现基于 Anthropic Skills 范式的技能管理系统，支持用户自定义
- 建立跨对话的长期记忆机制，实现个性化服务
- 引入 PlanChecker 子 Agent，消除结构性输出缺陷
- 接入高德地图服务，支持地理编码和可视化工作台
- 构建 RAG 知识库，支持对话知识的向量化检索
- 实现模型竞技场，支持多模型对比评测
- 系统性应对 AI 随机性，提升输出稳定性

### 5.3 PlanChecker 结构验证

**能力优化核心**：在输出前自动检查旅行计划的结构合规性。

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-301 | Agent 调用 finish 前自动运行 PlanChecker 验证 | P0 |
| FR-302 | 检查 8 条结构规则（闭环、不重复、交通一致等） | P0 |

**8 条结构规则**：

| 编号 | 规则 | 检查内容 |
|------|------|----------|
| 1 | 闭环行程 | 最后一天返回出发城市 |
| 2 | 餐厅不重复 | 整个行程不重复推荐同一家餐厅 |
| 3 | 景点不重复 | 整个行程不重复推荐同一个景点 |
| 4 | 交通一致性 | 城市间移动合理，交通方式一致 |
| 5 | 住宿合理性 | 住宿城市在行程路径上 |
| 6 | 天数覆盖 | 覆盖所有天数 |
| 7 | 城市覆盖 | 覆盖所有目的地城市 |
| 8 | 餐饮完整 | 每天有早/午/晚三餐 |

### 7.2 详细用例：UC-101 创建自定义技能

**前置条件**：用户已登录系统

**基本流程**：
1. 用户进入设置页或技能工坊
2. 点击"创建新技能"按钮
3. 填写技能信息：
   - 名称（英文标识，如 `my-custom-skill`）
   - 标题（中文名称，如"我的自定义技能"）
   - 描述（触发场景描述，供 LLM 判断是否激活）
   - 指令（详细的 SKILL.md 内容）
4. 前端调用 `POST /api/skills` 创建技能
5. 技能出现在"我的技能"列表中，默认启用
6. 下次对话时，Agent 的 System Prompt 中会包含该技能的元数据

**异常流程**：
- 名称重复：提示"技能名称已存在"
- 必填字段为空：前端表单校验拦截

**后置条件**：技能创建成功，Agent 可在后续对话中使用

### 7.3 详细用例：UC-301 结构验证与修正

**前置条件**：用户已发起旅行规划请求，Agent 正在 ReAct 循环中

**基本流程**：
1. Agent 经过多轮 Think-Act-Observe 收集信息
2. Agent 调用 `finish` 工具输出旅行计划
3. PlanChecker 拦截 finish 调用，运行 8 条结构规则检查
4. 检查结果：
   - **合规**：直接输出计划，流程结束
   - **不合规**：将违规项格式化为 feedback
5. 不合规时，违规反馈作为 tool result 注入对话：
   ```json
   {
     "status": "validation_failed",
     "violations": ["Day 3 dinner repeats restaurant from Day 1"],
     "message": "Please revise the plan..."
   }
   ```
6. Agent 在下一轮 ReAct 中看到违规反馈，自主修正计划
7. 再次调用 `finish`，再次检查（最多 2 轮）
8. 最终输出合规的旅行计划

**异常流程**：
- PlanChecker 自身异常：默认放行，输出当前计划
- 达到最大重试次数：输出当前计划（可能仍有问题）

**后置条件**：输出的旅行计划通过结构合规性检查

### 7.4 详细用例：UC-203 个性化规划

**前置条件**：用户有多次对话历史，长期记忆已积累

**基本流程**：
1. 用户发起请求："帮我规划三亚 5 天亲子游"
2. Agent 初始化时：
   - 从后端获取用户长期记忆
   - 记忆包含："用户有一个 5 岁孩子"、"偏好经济型酒店"、"之前去过北京"
3. 记忆注入 System Prompt 作为 "Personal Memories"
4. Agent 在规划时自动考虑：
   - 推荐亲子友好的景点（如海底世界、沙滩）
   - 选择经济型酒店（而非五星级）
   - 不推荐北京的景点（用户已去过）
5. 生成的计划天然符合用户偏好，无需额外沟通

**后置条件**：生成的旅行计划反映用户个性化偏好

```
User ──1:N──> AgentMemory (偏好卡片)
User ──1:N──> AgentMemoryChangeLog (审计日志)
TravelPlan ──1:N──> PlanActivity (结构化活动)
```

## 11. 验收标准（Acceptance Criteria）

### 11.1 功能验收

| 验收项 | 验收标准 |
|--------|----------|
| Skill 管理 | 内置 3 个技能，用户可创建/编辑/删除/启禁用自定义技能 |
| Skill 激活 | Agent 能根据用户需求自动激活匹配的技能 |
| 长期记忆 | 对话结束后自动提取用户事实，下次对话注入上下文 |
| 偏好管理 | 用户可在设置页管理偏好卡片 |
| PlanChecker | 生成的旅行计划通过 8 条结构规则检查 |
| Reflexion | 不合规计划自动触发修正循环，最终输出合规计划 |
| 高德集成 | 旅行计划中的地点自动补全经纬度坐标 |
| 知识检索 | Agent 可通过 knowledge_search 检索本地知识 |
| 上下文压缩 | 长对话自动压缩，不丢失关键信息 |
| 模型竞技场 | 支持双模型并行对比和投票 |

|--------|----------|
| 需求文档 | `docs/需求分析文档.md` 完整可查阅 |
