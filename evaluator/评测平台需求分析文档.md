# 评测平台需求分析文档

## 1. 项目概述

### 1.1 项目名称

TripAgent Evaluator - 智能旅游 Agent 评测平台

### 1.2 项目背景

本项目所实现的评测平台面向 Agent 回答质量、工具调用过程、模型性能、模型安全性和多模型对比等场景，提供任务化、可视化、可追溯的自动化评测能力。

随着 Agent 系统引入 ReAct、Plan-and-Execute、Reflection 等复杂推理框架，仅依靠人工观察很难稳定判断 Agent 的输出质量和版本变化影响。因此，需要构建独立的评测平台，对不同模型、不同策略和不同版本的 Agent 进行批量测试、指标统计和结果对比。

### 1.3 项目目标

构建一个面向智能旅游 Agent 的评测系统，支持数据集管理、评测任务创建、批量运行、样本级诊断、模型评分、运行对比和结果导出，帮助开发与评估人员持续验证 Agent 的效果、安全和性能。

## 2. 背景与目标

### 2.1 业务背景

智能旅游规划助手需要面向真实用户生成行程、景点推荐、交通建议、预算说明和旅行提醒。此类输出具有明显的开放性和主观性，传统单元测试难以覆盖回答质量、事实一致性、工具调用合理性等问题。

评测平台通过预置数据集和可配置评测策略，将 Agent 的回答质量转化为可观察、可比较、可追踪的指标，支持团队在模型升级、Prompt 调整、工具变更和功能迭代时快速发现回归问题。

### 2.2 技术背景

评测平台采用前后端分离架构：

- 前端基于 Vue 3 + TypeScript，提供任务、模型、数据集、策略和运行结果管理界面。
- 后端基于 Spring Boot，负责任务编排、评测执行、指标计算、结果持久化和 SSE 状态推送。
- Agent 评测服务基于 FastAPI，提供流式问答接口和 Ragas 语义评分接口。

系统支持规则评测、LLM-as-a-Judge、Ragas 语义评分和 Bradley-Terry 多模型排名等方法。

### 2.3 目标

- 构建可创建、执行和追踪的评测任务体系
- 支持数据集上传、样本预览和样本级结果记录
- 支持规则评测、Judge 评测和混合评测
- 支持多模型成对比较与 Bradley-Terry 排名
- 支持运行过程可视化和 SSE 状态推送
- 支持运行结果对比、导出和审计

## 3. 范围（Scope）

### 3.1 包含范围

| 模块 | 功能 |
|------|------|
| 评测任务管理 | 创建任务、编辑任务、启动任务、取消任务、删除任务、查看历史运行 |
| 数据集管理 | 上传数据集、查询数据集、预览样本、软删除数据集 |
| 模型管理 | 注册参评模型、注册裁判模型、维护模型参数和启用状态 |
| 策略管理 | 创建评测策略、配置指标、配置权重、配置阈值、自定义指标 |

| 语义评分 | 调用 Ragas 或裁判模型进行回答质量评分 |
| 多模型对比 | Pairwise Judge、比较结果落库、Bradley-Terry 排名 |
| 结果展示 | 运行详情、样本结果、指标总览、模型排行 |
| 结果导出 | 运行对比导出、导出重试、下载、审计和一致性检查 |

- 面向公网的生产级权限体系
- 大规模分布式压测平台
- 完整 MLOps 模型训练与部署能力
- 第三方商业评测平台深度集成
- 自动修复 Agent 代码或 Prompt 的闭环系统
- 长期归档型数据仓库建设

## 5. 功能需求（Functional Requirements）

### 5.1 评测任务管理

- FR-001: 系统应支持创建评测任务，包含任务名称、Agent 版本、数据集、评测模式、评测方法和评测维度
- FR-002: 系统应支持编辑任务配置，包括评测策略、参评模型、裁判模型和采样策略
- FR-003: 系统应支持启动评测任务，并生成一次独立的 EvalRun 运行记录
- FR-004: 系统应支持取消正在运行的任务
- FR-005: 系统应支持删除评测任务
- FR-006: 系统应支持查看任务的历史运行列表和运行状态

### 5.2 数据集管理

- FR-007: 系统应支持上传 CSV 或 JSON 格式评测数据集
- FR-008: 系统应支持查询数据集列表和数据集详情
- FR-009: 系统应支持预览数据集样本
- FR-010: 系统应支持软删除数据集，避免误删历史运行依赖数据
- FR-011: 数据集样本应至少包含 question、groundTruth 等评测字段

### 5.3 模型管理

- FR-012: 系统应支持创建模型配置，包含模型标识、显示名称、Base URL、角色和启用状态
- FR-013: 系统应支持区分参评模型（PLAYER）和裁判模型（JUDGE）
- FR-014: 系统应支持启用、禁用、编辑和软删除模型配置
- FR-015: 系统应支持在任务中选择一个或多个参评模型
- FR-016: 系统应支持在 Judge 或 BT 评测中指定裁判模型

### 5.4 评测策略管理

- FR-017: 系统应支持创建和维护评测策略
- FR-018: 策略应支持配置指标定义、维度权重和阈值规则
- FR-019: 系统应支持创建自定义指标
- FR-020: 任务创建时应支持应用已有评测策略
- FR-021: 任务应保存实际使用的 strategyConfig，确保历史运行可追溯

### 5.5 评测执行

- FR-022: 系统应支持按数据集样本批量调用 Agent 或指定模型
- FR-023: 系统应记录每条样本的输入、期望输出、实际输出和错误信息
- FR-024: 系统应记录首字延迟、端到端延迟和 Token 使用量
- FR-025: 系统应支持 PROCESS 模式下保存工具调用轨迹
- FR-026: 系统应在单条样本失败时继续执行后续样本
- FR-027: 系统应在运行完成后生成运行级指标快照

### 5.6 评测方法

- FR-028: 系统应支持 DETERMINISTIC 规则评测
- FR-029: 系统应支持 JUDGE 语义评测
- FR-030: 系统应支持 HYBRID 混合评测
- FR-031: 系统应支持调用 Ragas 计算 faithfulness 和 answer_correctness 指标
- FR-032: 系统应支持按 EFFECTIVENESS、SAFETY、PERFORMANCE、OVERALL 维度计算结果

### 5.7 多模型对比与排名

- FR-033: 系统应支持选择多个参评模型进行同一数据集评测
- FR-034: 系统应支持按照 ALL_PAIRS 等策略生成模型比较对
- FR-035: 系统应支持裁判模型对两个模型回答进行成对比较
- FR-036: 系统应保存每一次模型比较结果到 eval_comparison
- FR-037: 系统应基于 Bradley-Terry 模型计算模型能力参数 theta
- FR-038: 系统应将 theta 转换为 Elo 分数，供前端展示
- FR-039: 系统应支持展示置信区间、胜率、比较次数、平均耗时、平均 Token 和完成率

### 5.8 运行结果展示

- FR-040: 系统应展示运行状态、成功数、失败数、总样本数和运行时间
- FR-041: 系统应展示运行级指标，包括完成率、效果分、安全分、性能分和 Token 消耗
- FR-042: 系统应展示样本级记录，包括输入、输出、错误、耗时和工具轨迹
- FR-043: 系统应支持按运行维度对比 baselineRun 与 targetRun
- FR-044: 系统应支持只展示发生变化的样本差异
- FR-045: 系统应支持按 Elo、胜率、延迟、Token、完成率等方式查看模型排行

### 5.9 SSE 状态推送

- FR-046: 系统应支持前端订阅运行状态流
- FR-047: 系统应在运行开始、样本完成、取消请求、运行终止等节点推送事件
- FR-048: SSE 断开不应影响后端评测任务继续执行
- FR-049: 已完成或失败的运行在订阅时应返回最终状态

### 5.10 导出与审计

- FR-050: 系统应支持创建运行对比导出任务
- FR-051: 系统应支持查询导出任务列表和详情
- FR-052: 系统应支持下载导出文件
- FR-053: 系统应支持导出失败后的重试
- FR-054: 系统应支持删除和批量删除导出任务
- FR-055: 系统应记录导出审计日志
- FR-056: 系统应支持导出文件一致性检查

## 6. 非功能需求（Non-Functional Requirements）

### 6.1 性能要求

- NFR-001: 普通查询接口响应时间应小于 500ms（不含数据库冷启动和外部模型调用）
- NFR-002: 评测运行状态 SSE 事件推送延迟应小于 2 秒
- NFR-003: 单条样本模型调用应设置超时时间，避免任务永久阻塞
- NFR-004: 运行详情页应支持至少数百条样本记录的查询和展示
- NFR-005: 多模型评测应控制比较对数量，避免组合爆炸导致执行时间不可控

### 6.2 可用性要求

- NFR-006: 单条样本失败不应导致整轮评测中断
- NFR-007: Ragas 或裁判模型不可用时，应记录 warning 或错误信息
- NFR-008: 导出失败应支持重试
- NFR-009: 后端重启后应能识别未完成运行，并进行状态恢复或失败标记

### 6.3 可扩展性要求

- NFR-010: 评测方法应支持后续扩展新的 Judge 或指标算法
- NFR-011: 模型网关应支持 OpenAI-Compatible 模型切换
- NFR-012: 数据集解析逻辑应支持后续扩展更多文件格式
- NFR-013: 排名算法应与评测执行流程解耦，便于替换或升级

### 6.4 安全性要求

- NFR-014: 模型 API Key 等敏感配置不得硬编码在代码中
- NFR-015: 上传数据集应限制文件类型和文件大小
- NFR-016: 导出下载接口应校验导出任务存在性和文件一致性
- NFR-017: 删除操作应优先采用软删除，避免破坏历史评测数据
- NFR-018: 前端不应展示明文密钥

### 6.5 可观测性要求

- NFR-019: 关键任务状态变化应记录日志
- NFR-020: 样本失败时应记录 errorCode 和 errorMessage
- NFR-021: 外部模型、Agent 和 Ragas 调用应记录耗时和异常
- NFR-022: 导出任务应保留操作审计记录

### 7.2 详细用例：UC-002 执行评测任务

**前置条件**：评测任务已创建，任务绑定的数据集和模型配置可用

**基本流程**：

1. 用户在任务列表中点击“启动任务”
2. 前端调用后端任务启动接口
3. 后端创建 EvalRun 运行实例，并将任务状态置为 RUNNING
4. EvalRunService 异步加载数据集样本
5. 系统按样本逐条调用 Agent 或参评模型生成回答
6. 系统记录 QARecord，包括输入、输出、耗时、Token 和错误信息
7. 若任务配置为 JUDGE 或 HYBRID，系统调用 Ragas 或裁判模型评分
8. 若任务满足多模型 BT 条件，系统生成模型对并执行成对比较
9. 系统聚合生成 MetricSnapshot
10. 系统计算模型排名并写入 ModelRating
11. 后端更新 EvalRun 和 EvalTask 状态
12. 前端通过 SSE 展示运行过程和最终状态

**异常流程**：

- 如果某条样本调用失败，记录错误并继续执行后续样本
- 如果评测运行被取消，后端记录取消请求并终止后续样本执行
- 如果裁判模型不可用，记录 Judge 错误并保留已有样本结果
- 如果 BT 排名数据不足，跳过排名但保留比较和 QA 记录

**后置条件**：运行结束后，用户可查看运行详情、指标快照、样本记录和模型排名

## 8. 数据需求

### 8.1 核心实体

| 实体 | 说明 | 存储方式 |
|------|------|----------|
| EvalTask | 评测任务配置 | 数据库 |
| EvalRun | 单次评测运行 | 数据库 |
| QARecord | 样本级问答记录 | 数据库 |
| MetricSnapshot | 运行级指标快照 | 数据库 |
| EvalStrategy | 评测策略 | 数据库 |
| CustomMetric | 自定义指标 | 数据库 |
| Dataset | 数据集元信息 | 数据库 |
| DatasetSample | 数据集样本 | 数据库 |
| ModelProfile | 模型配置 | 数据库 |
| EvalComparison | 模型成对比较结果 | 数据库 |
| ModelRating | 模型排名结果 | 数据库 |
| EvalExportTask | 导出任务 | 数据库 |
| EvalExportAudit | 导出审计日志 | 数据库 |
| ExportFile | 导出文件 | 文件系统 |

### 8.2 数据模型关系

- EvalTask 1:N EvalRun（一个任务可产生多次运行）
- EvalRun 1:N QARecord（一次运行包含多条样本记录）
- EvalRun 1:1 MetricSnapshot（一次运行对应一个指标快照）
- EvalRun 1:N EvalComparison（一次多模型运行包含多条比较结果）
- EvalRun 1:N ModelRating（一次运行包含多个模型排名结果）
- Dataset 1:N DatasetSample（一个数据集包含多条样本）
- EvalTask N:1 Dataset（任务引用一个数据集）
- EvalTask N:M ModelProfile（任务选择多个参评模型）
- EvalTask N:1 ModelProfile（任务可引用一个裁判模型）
- EvalExportTask N:1 EvalTask（导出任务关联评测任务）

| 接口 | 路径 | 方法 | 说明 |

### 9.4 SSE事件格式

评测运行通过 SSE 返回以下事件类型：

- `run_state`: 当前运行状态
- `run_cancel_requested`: 取消请求已接收
- `sample_started`: 样本开始执行
- `sample_finished`: 样本执行完成
- `metric_updated`: 指标更新
- `run_terminated`: 运行结束
- `error`: 错误信息

## 10. 约束与假设

### 10.1 约束

| 约束 | 说明 |
|------|------|
| 技术栈约束 | 前端使用 Vue 3，后端使用 Spring Boot，Agent 使用 FastAPI |
| 模型接口约束 | 模型调用以 OpenAI-Compatible API 为主 |
| 评测成本约束 | Judge 和多模型 BT 评测会增加 Token 成本 |
| 数据规模约束 | 初期以中小规模评测数据集为主 |
| 执行时间约束 | 多模型、多维度、多样本组合会显著增加运行时间 |

### 10.2 假设

| 假设 | 说明 |
|------|------|
| Agent 可用性 | 被评测 Agent 服务能够正常响应 |
| 模型可用性 | 参评模型和裁判模型配置正确并可调用 |
| 数据集质量 | 上传数据集字段完整，样本内容可用于评测 |
| 网络可用性 | 后端能够访问 Agent、Ragas 和模型服务 |
| 评测策略合理性 | 评估人员能够配置符合任务目标的指标与权重 |

## 11. 验收标准（Acceptance Criteria）

### 11.1 功能验收

| 验收项 | 验收标准 |
|--------|----------|
| 任务管理 | 能够创建、编辑、启动、取消和删除评测任务 |
| 数据集管理 | 能够上传数据集并预览样本 |
| 模型管理 | 能够创建参评模型和裁判模型配置 |
| 策略管理 | 能够创建评测策略和自定义指标 |
| 批量运行 | 能够基于数据集完成一次端到端评测运行 |
| 样本记录 | 能够保存并展示每条样本的输入、输出、错误和耗时 |
| 指标聚合 | 能够生成运行级 MetricSnapshot |
| 多模型对比 | 能够生成比较结果并计算模型排名 |
| 运行对比 | 能够对比两次运行的指标和样本差异 |
| 导出能力 | 能够创建、查询、下载和重试导出任务 |
