# Evaluator - Travel Agent Evaluation Platform

Spring Boot + Vue + FastAPI 评测平台，负责创建评测任务、管理数据集与模型配置、批量运行旅行 Agent / 大模型回答，并通过确定性规则、Ragas judge、Bradley-Terry 多模型对比等方式生成评测结果。

本说明聚焦本地运行、接口契约和联调排障；功能设计与交付记录请参考 [README.md](./README.md)。

## 1. 技术栈

- Java 17
- Spring Boot 3.2
- Spring Web / WebFlux / JPA
- H2 Database
- Python 3.10+
- FastAPI
- Uvicorn
- Ragas / LangChain / OpenAI-compatible APIs
- Vue 3
- TypeScript
- Vite
- Axios / Vue Router

## 2. 模块架构

```text
evaluator/
   docker-compose.yml              # 三端容器化启动配置
   backend/
      pom.xml                       # Spring Boot 后端依赖
      src/main/resources/
         application.yml            # 后端端口、H2、Agent、LLM、BT 配置
         db/schema.sql              # H2 建表脚本
         datasets/                  # 内置评测数据集
      src/main/java/com/tripagent/backend/
         controller/                # 健康检查、聊天代理、评测 API
         controller/eval/           # 任务、策略、模型、数据集、评分、导出接口
         service/eval/              # 评测编排、指标聚合、BT 拟合、导出等核心逻辑
         service/llm/               # OpenAI-compatible 模型调用网关
         entity/                    # JPA 实体与枚举
         repository/                # JPA Repository
         dto/eval/                  # 评测 API 请求与响应模型
   agent/
      requirements.txt              # FastAPI / Ragas 依赖
      app/main.py                   # FastAPI 入口
      app/api/routes.py             # /agent/chat/stream SSE 接口
      app/api/eval_routes.py        # /eval/ragas/score Ragas 评分接口
      app/services/chat_service.py  # 演示 Agent 流式回答
      app/services/ragas_service.py # Ragas judge 封装
      app/services/tool_service.py  # 演示工具轨迹
   frontend/
      package.json                  # Vue / Vite 依赖与脚本
      src/api/client.ts             # 后端 API 与 SSE 客户端
      src/router/index.ts           # 页面路由
      src/views/                    # 总览、任务、历史、详情、监控、模型、数据集、配置页
      src/components/               # 创建任务、模型选择、BT 排名、管理面板等组件
```

核心流程：

1. 前端访问 `http://localhost:5173`，通过 `src/api/client.ts` 调用后端 `/api/eval/**`。
2. 后端创建 `EvalTask`，用户启动后生成 `EvalRun` 并异步执行。
3. 普通评测会逐条读取数据集样本，调用 Python Agent SSE 或指定模型生成回答。
4. `JUDGE` / `HYBRID` 任务会调用 Agent 的 `/eval/ragas/score` 获取 Ragas 分数。
5. 多模型任务会让多个 player 模型回答，再由 judge 模型做 pairwise 对比，并用 Bradley-Terry 拟合 Elo 排名。
6. 后端将 `qa_record`、`metric_snapshot`、`eval_comparison`、`model_rating` 等结果写入 H2。
7. 前端通过运行详情页和 SSE 监控页展示任务进度、样本结果、指标和排名。

## 3. 环境准备

在 `evaluator` 目录或各子目录执行下面的命令。

### 3.1 Backend

需要本机有 Java 17 和 Maven。

```powershell
cd evaluator\backend
mvn -DskipTests compile
```

后端默认使用本地 H2 文件数据库：

```text
evaluator/backend/data/tripagent
```

如果希望每次重启清空数据，可以启动时使用 `dev` profile：

```powershell
mvn spring-boot:run "-Dspring-boot.run.profiles=dev"
```

### 3.2 Agent

需要 Python 3.10+。Ragas judge 需要联网访问 OpenAI-compatible 模型服务；只跑演示 Agent 流式回答时可以先不配置 Key。

```powershell
cd evaluator\agent
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

常用环境变量：

```powershell
$env:MODELSCOPE_API_KEY="your-modelscope-key"
$env:MODELSCOPE_BASE_URL="https://api-inference.modelscope.cn/v1"
$env:RAGAS_JUDGE_MODEL="Qwen/Qwen3-235B-A22B-Instruct-2507"
```

### 3.3 Frontend

需要 Node.js 20+。

```powershell
cd evaluator\frontend
npm install
```

前端 API 地址目前在 `src/api/client.ts` 中固定为：

```text
http://localhost:8080/api
```

## 4. 启动服务

### 方式 A：Docker Compose 一键启动

```powershell
cd evaluator
docker compose up --build
```

默认端口：

- Frontend: `http://localhost:5173`
- Backend: `http://localhost:8080`
- Agent: `http://localhost:8000`

### 方式 B：本地三端启动

终端 1：启动 Agent。

```powershell
cd evaluator\agent
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

终端 2：启动 Backend。

```powershell
cd evaluator\backend
mvn spring-boot:run
```

终端 3：启动 Frontend。

```powershell
cd evaluator\frontend
npm run dev
```

健康检查：

- Backend: `GET http://localhost:8080/api/health`
- Agent: `GET http://localhost:8000/health`
- H2 Console: `http://localhost:8080/h2-console`

H2 JDBC URL 默认使用：

```text
jdbc:h2:./data/tripagent
```

## 6. 与后端联调

推荐联调顺序：

1. 启动 Agent，访问 `http://localhost:8000/health` 确认服务可用。
2. 启动 Backend，访问 `http://localhost:8080/api/health` 确认后端可用。
3. 打开 H2 Console，确认 `dataset`、`model_profile` 等启动 seed 数据已写入。
4. 启动 Frontend，访问 `http://localhost:5173`。
5. 在“模型管理”中确认 player / judge 模型存在且启用。
6. 在“数据集管理”中确认内置数据集或上传数据集存在。
7. 在“AI 评测配置”中创建或选择一套配置。
8. 在“评测任务”中创建任务并启动，进入运行详情或监控页观察 SSE 事件。

如果只验证基础链路，优先创建 `DETERMINISTIC + RESULT` 任务；如果要验证 Ragas，需要配置 `MODELSCOPE_API_KEY`；如果要验证 BT，需要至少两个 player 模型和一个 judge 模型。

## 7. 常见问题

- Backend 无法调用 Agent：确认 Agent 在 `8000` 端口启动，并检查后端 `agent.base-url` 或环境变量 `AGENT_BASE_URL`。
- Ragas 一直返回 fallback `0.5`：通常是 `MODELSCOPE_API_KEY` 未配置、模型服务不可达、Ragas 依赖未安装完整，或所选 metric 需要额外 embedding 能力。
- `/api/eval/llm/ping` 失败：确认模型配置里的 `apiKeyRef` 对应环境变量存在，默认常用 `MODELSCOPE_API_KEY`。
- 前端请求失败：确认 Backend 在 `8080` 端口启动，因为前端客户端固定请求 `http://localhost:8080/api`。
- H2 数据不是预期状态：默认文件数据库会保留历史数据；如需干净环境，使用 `dev` profile 的内存库，或删除 `evaluator/backend/data` 后重启。
- 上传数据集失败：当前只支持 `.json` / `.csv`，文件大小默认不超过 `1MB`，样本数默认不超过 `200`。
- 运行任务没有实时进度：确认前端能连接 `GET /api/eval/runs/{runId}/stream`，并且浏览器没有阻止 SSE 连接。
- 端口冲突：检查 `5173`、`8080`、`8000` 是否已被其他进程占用。
