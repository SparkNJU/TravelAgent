# 评测平台设计详细文档

## 一、概述

### 1.1 模块定位

评测平台模块是 TravelMind 智能旅行系统的质量保障与模型对比中心，负责对 Agent 或候选模型进行批量测试、过程监控、指标计算、结果对比和排名分析。

该模块采用三层架构实现：

- `evaluator/frontend`：评测控制台前端
- `evaluator/backend`：评测编排与数据管理后端
- `evaluator/agent`：评测专用 Agent / Judge 服务

整体上，它是一个独立于主业务平台的平行子系统，默认通过 HTTP/SSE 与模型网关、评测 Agent 和前端页面通信。

### 1.2 核心能力

| 能力 | 说明 |
|------|------|
| **任务化评测** | 支持创建评测任务，绑定数据集、模型、评测方式和维度配置 |
| **批量执行** | 对数据集样本逐条执行推理与评分，生成运行记录 |
| **多评测方法** | 支持 `DETERMINISTIC`、`JUDGE`、`HYBRID` 三类评测方式 |
| **过程可观测** | 支持按运行维度推送 SSE 事件，实时展示运行状态 |
| **样本级诊断** | 保存输入、输出、错误、工具轨迹、耗时、Token 等样本信息 |
| **模型对比排序** | 基于 Pairwise Judge + Bradley-Terry 对多模型进行排名 |
| **结果导出审计** | 支持对比结果导出、重试、删除、一致性检查与审计追踪 |

### 1.3 技术栈

| 组件 | 技术 |
|------|------|
| 前端 | Vue 3 + TypeScript + Vite |
| 后端 | Spring Boot 3.2 + Java 17 + Spring Data JPA + WebFlux |
| 评测 Agent | FastAPI + Pydantic + Uvicorn |
| Judge / LLM | OpenAI-Compatible API |
| 语义评测 | Ragas |
| 排名算法 | Bradley-Terry + Bootstrap CI + Elo 转换 |
| 数据存储 | H2 / SQL Schema（可迁移到 MySQL） |
| 流式通信 | Server-Sent Events (SSE) |

## 三、核心组件设计

### 3.1 EvalTaskService（评测任务管理）

**文件**：`evaluator/backend/src/main/java/com/tripagent/backend/service/eval/EvalTaskService.java`

EvalTaskService 负责评测任务的创建、更新、启动、取消、删除与查询，是整个评测流程的入口。

#### 类职责

```java
class EvalTaskService {
    createTask(request)         // 创建任务
    updateTask(taskId, request) // 更新任务
    startTask(taskId)           // 启动评测
    cancelTask(taskId)          // 取消最新运行
    deleteTask(taskId)          // 删除任务
    listTaskRuns(taskId, ...)   // 查看任务历史运行
}
```

#### 设计要点

- 任务定义评测目标，而非一次具体执行。
- 一个任务可关联多次 `EvalRun`。
- 任务中固化数据集、评测模式、评测方法、评测维度、策略配置、参评模型与裁判模型。
- 启动任务时，仅创建运行实例并交由 `EvalRunService` 异步执行。

### 3.2 EvalRunService（评测执行引擎）

**文件**：`evaluator/backend/src/main/java/com/tripagent/backend/service/eval/EvalRunService.java`

EvalRunService 是评测平台的核心执行模块，负责驱动单次运行的全流程，包括样本加载、模型调用、评分、聚合、事件推送和结果落库。

#### 类设计

```java
class EvalRunService {
    createRunForTask(task)
    executeRunAsync(runId)
    getRunRecords(runId)
    getRunMetrics(runId)
    compareRuns(taskId, baselineRunId, targetRunId, changedOnly)
    openRunStream(runId)
}
```

#### 执行模式

EvalRunService 会根据任务配置选择不同执行路径：

| 路径 | 说明 |
|------|------|
| 普通单模型 / Agent 评测 | 调用指定模型或 Agent，逐样本生成回答并评分 |
| Judge 语义评测 | 通过裁判模型或 Ragas 对回答进行语义评分 |
| BT 多模型对比评测 | 对多个模型进行成对比较，再使用 Bradley-Terry 排名 |

#### 核心能力

- 维护 `run -> SSE emitters` 的流式订阅关系。
- 支持运行取消。
- 支持样本级记录 `qa_record`。
- 支持运行级聚合 `metric_snapshot`。
- 支持运行间 diff 比较。

### 3.3 EvalStrategyService（评测策略管理）

**文件**：`evaluator/backend/src/main/java/com/tripagent/backend/service/eval/EvalStrategyService.java`

评测策略定义“如何评”，用于将评测规则从任务中抽象出来，供多个任务复用。

#### 核心内容

| 配置项 | 说明 |
|------|------|
| `metricDefinitions` | 指标定义列表 |
| `weightConfig` | 多维度权重配置 |
| `thresholdConfig` | 阈值与门禁规则 |
| `strategyName` | 策略名称 |
| `custom metrics` | 自定义指标引用 |

#### 接口层

| 接口 | 说明 |
|------|------|
| `POST /api/eval/strategies` | 创建评测策略 |
| `GET /api/eval/strategies` | 查询策略列表 |
| `GET /api/eval/strategies/{strategyId}` | 查询策略详情 |
| `PUT /api/eval/strategies/{strategyId}` | 更新策略 |
| `POST /api/eval/metrics/custom` | 创建自定义指标 |
| `GET /api/eval/metrics/custom` | 查询自定义指标 |

#### 设计要点

- 当前实现中，策略已去版本化。
- 任务创建时可将策略内容复制进 `strategyConfig`。
- 后续即便策略模板变化，也不影响历史运行的可回放性。

### 3.6 AgentGateway / RagasGateway / LlmGateway（三类执行网关）

#### AgentGatewayService

负责调用评测 Agent 的 `/agent/chat/stream` 接口，获取流式回答，供后端转为 `qa_record` 与过程事件。

#### RagasGatewayService

负责调用 FastAPI Agent 的 `/eval/ragas/score` 接口，对样本批量进行语义评分。

当前支持指标：

- `faithfulness`
- `answer_correctness`

#### LlmGateway

负责直连 OpenAI-compatible 大模型接口，用于普通模型调用、裁判模型比较和结构化 Judge 输出。

### 3.7 RatingService（模型排名引擎）

**文件**：`evaluator/backend/src/main/java/com/tripagent/backend/service/eval/RatingService.java`

RatingService 负责将成对比较结果拟合为模型排名结果。

#### 处理流程

```text
eval_comparison
  → 按 dimension 分组
  → Bradley-Terry 拟合 theta
  → EloConverter 转换为 Elo
  → BootstrapCi 计算 95% CI
  → 聚合 QA 统计信息
  → 写入 model_rating
```

#### 输出字段

| 字段 | 说明 |
|------|------|
| `theta` | BT 潜在能力参数 |
| `elo` | 展示用评分 |
| `lower_ci_95` / `upper_ci_95` | 置信区间 |
| `n_comparisons` | 对比次数 |
| `n_wins` | 胜场 |
| `win_rate` | 胜率 |
| `avg_latency_ms` | 平均时延 |
| `avg_tokens` | 平均 Token |
| `completion_rate` | 完成率 |

#### Overall 合成

默认权重：

```text
EFFECTIVENESS = 0.5
SAFETY        = 0.2
PERFORMANCE   = 0.3
```

如任务 `strategyConfig.weightConfig` 有配置，则优先使用任务权重。

### 3.8 EvalExportService（导出与审计）

该模块负责运行对比结果的导出、重试、下载、删除和一致性检查。

## 四、评测框架详解

### 4.1 Evaluation Mode（评测模式）

| 模式 | 含义 | 适用场景 |
|------|------|----------|
| `RESULT` | 只看输入与最终回答 | 关注回答质量本身 |
| `PROCESS` | 同时检查工具轨迹与过程信息 | 关注 Agent 推理与工具使用质量 |

### 4.2 Evaluation Method（评测方法）

| 方法 | 含义 | 实现方式 |
|------|------|----------|
| `DETERMINISTIC` | 基于规则匹配计算得分 | 本地规则计算 |
| `JUDGE` | 使用裁判模型或 Ragas 语义评分 | LLM / Ragas |
| `HYBRID` | 规则分与 Judge 分混合 | 默认可按 0.5 / 0.5 组合 |

#### 典型公式

```text
DETERMINISTIC: finalScore = deterministicScore
JUDGE:         finalScore = judgeScore
HYBRID:        finalScore = 0.5 * deterministicScore + 0.5 * judgeScore
```

### 4.3 Evaluation Dimension（评测维度）

系统支持：

- `EFFECTIVENESS`
- `SAFETY`
- `PERFORMANCE`
- `OVERALL`

其中：

| 维度 | 说明 |
|------|------|
| `EFFECTIVENESS` | 答案是否有效、完整、符合预期 |
| `SAFETY` | 是否存在不安全内容、风险建议或错误引导 |
| `PERFORMANCE` | 响应速度、Token 成本、完成效率 |
| `OVERALL` | 多维度加权综合分 |

### 4.4 普通评测流程

```text
创建任务
  → 启动任务
  → 创建 EvalRun
  → 加载数据集样本
  → 调用 Agent 或指定模型
  → 记录 qa_record
  → 调用 judge / ragas 评分
  → 聚合 metric_snapshot
  → 更新 run/task 状态
```

### 4.5 BT 多模型评测流程

触发条件：

```text
evaluationMethod in {JUDGE, HYBRID}
selectedModelIds >= 2
judgeModelId != null
```

执行链路：

```text
每条样本
  → 各 player 模型生成回答
  → 写入多条 qa_record
  → 生成模型对
  → 裁判模型按维度比较 A / B
  → 写入 eval_comparison
全部样本完成后
  → RatingService 计算 BT 排名
  → 写入 model_rating
```

### 4.6 Ragas 语义评测流程

```text
Java Backend
  → 组织 samples(question, answer, groundTruth, contexts)
  → POST /eval/ragas/score
  → Python Agent 调用 Ragas
  → 返回各指标 scores + mean
  → 后端合并进样本分与运行指标
```

## 六、数据流与通信

### 6.1 请求处理全流程

```text
Frontend 创建任务
  → Backend 保存 EvalTask
  → Frontend 启动任务
  → Backend 创建 EvalRun
  → EvalRunService 异步执行
  → 调用 Agent / LLM / Ragas
  → 写入 QARecord、Comparison、MetricSnapshot、ModelRating
  → Frontend 订阅 run SSE 查看状态
```

### 6.2 SSE 流式事件

运行详情页通过 `openRunStream(runId)` 建立 SSE 连接，接收运行状态事件。

典型事件：

| 事件 | 说明 |
|------|------|
| `run_state` | 当前运行状态 |
| `run_cancel_requested` | 用户请求取消 |
| `sample_started` | 样本开始执行 |
| `sample_finished` | 样本执行结束 |
| `metric_updated` | 指标更新 |
| `run_terminated` | 运行完成或失败 |

### 6.3 外部调用协议

#### Backend → Agent

```text
GET /agent/chat/stream
```

参数：

| 参数 | 说明 |
|------|------|
| `sessionId` | 会话 ID |
| `question` | 当前样本问题 |

#### Backend → Agent(Ragas)

```text
POST /eval/ragas/score
```

请求体：

```json
{
  "samples": [
    {
      "question": "用户问题",
      "answer": "模型回答",
      "groundTruth": "参考答案",
```

响应体：


## 七、错误处理与容错

### 7.1 分层容错策略

| 层级 | 场景 | 策略 |
|------|------|------|
| Agent 调用层 | Agent 不可达、SSE 中断 | 记录样本失败，继续后续样本 |
| Judge 层 | 裁判模型异常 | 写入错误原因，必要时降级 |
| Ragas 层 | NaN、超时、服务不可用 | 返回 fallback 分或 warning |
| 排名层 | 比较结果不足 | 跳过维度拟合，不阻断整轮运行 |
| 导出层 | 文件生成失败 | 支持 retry 与 audit |
| 全局层 | 未捕获异常 | 更新 run/task 为失败并推送终止事件 |

### 7.2 降级策略

- Ragas 不可用时，仅保留规则分或已有 Judge 分。
- BT 比较数据不足时，不生成排名但保留 QA 样本。
- 某个样本失败时，不中断整轮任务。
- 导出失败时，不影响原始评测结果查询。

## 九、模式组合总结

| 模式 | 组合能力 | 适用场景 |
|------|----------|----------|
| 单模型规则评测 | `RESULT/PROCESS + DETERMINISTIC` | 快速回归测试 |
| 单模型语义评测 | `RESULT/PROCESS + JUDGE` | 检查回答质量 |
| 混合评测 | `RESULT/PROCESS + HYBRID` | 平衡规则与语义判断 |
| 多模型排名评测 | `JUDGE/HYBRID + BT` | 比较多个候选模型优劣 |
| 运行对比导出 | `Run Compare + Export` | 版本回归分析、汇报输出 |
